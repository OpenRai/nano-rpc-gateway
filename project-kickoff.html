A Nano RPC gateway.

A gradual path from action-shaped, loosely defined RPC toward versioned JSON-RPC 2.0, machine-checkable schemas, and Server-Sent Events—without breaking existing clients.

POC: evidence-first, not feature-count first

The promise

Semantic equivalence for named node versions and explicit methods—not byte-preserving proxying, assumed parity, or an unbounded public node surface.

The integration problem

Native Nano interfaces work, but make every integrator reconstruct the contract.

Action-shaped HTTP RPC, loosely structured errors, and a separate WebSocket event protocol spread compatibility and recovery logic across every wallet, explorer, exchange, and SDK.

The technical addition

Add a formal interface without replacing the node.

Run a gateway alongside Nano or RsNano. It translates the existing action-based RPC and WebSocket messages into JSON-RPC methods and SSE events, each described by versioned, machine-checkable schemas. Native clients and node P2P remain unaffected.

Architecture

Translate Nano once, then offer it in two ways.

One internal translator turns native Nano RPC replies and WebSocket messages into gateway responses and events. JSON-RPC uses it for calls; SSE uses it for updates, so they do not disagree about an error, confirmation, or reconnect.

01

Clients can learn the API—or bring one already generated

The gateway can publish a machine-readable list of supported calls, inputs, and outputs. Tooling can use it to generate a client; that client can bundle the same information and never ask the server at runtime.

02

Live updates with a clear reconnect path

While the gateway is running, a reconnecting client can ask for events after its last event ID. If those events are no longer available, the gateway says so and the client queries JSON-RPC for the current state.

03

Adopt it without breaking existing clients

The gateway can run alongside native RPC and WebSocket endpoints while clients phase over. A hardened deployment may later expose only the gateway; Nano’s node-to-node P2P protocol is a separate concern.

04

Compatibility is measured

Reports distinguish static inventory, schema validity, and live scenario coverage as PASS, FAIL, or NOT TESTED.

POC finish line

Prove one complete flow—not a decorative proxy.

Use precomputed work on a deterministic development network so gateway evidence never depends on probabilistic PoW timing.

Discover

A generic client calls rpc.discover and validates the served OpenRPC contract.

Read

Call account_info through standards-valid JSON-RPC.

Submit

Publish a valid, precomputed-work state block through process.

Observe

Receive its normalized confirmation as a browser-compatible SSE event.

Recover

Reconnect with Last-Event-ID; replay or receive reset and reconcile through RPC.

Evidence gates

What we will refuse to hand-wave.

Equivalence

Only assert it for a named node version, configuration, and method profile with recorded scenarios. The gateway is not a transparent byte proxy.

Gate: fixtures + public scenario

Streaming

Never silently drop overflow or imply durable ordering. A stream loss yields a visible control event and a documented state query.

Gate: slow client + reset tests

Efficiency

Do not claim low footprint from a language choice. Publish repeatable RSS, startup, RPC, and fan-out measurements with raw artifacts.

Gate: benchmark harness + results
