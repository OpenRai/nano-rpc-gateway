Account confirmation stream

Open GET /events/confirmations and filter by accounts or hashes. Each SSE record contains a JSON-RPC notification. Send Last-Event-ID when reconnecting.

Account tracking

Watch accounts and update local state

Use this sequence to track a send or receive from submission to cementing. The stream reports cemented blocks only. It does not report votes or election progress.

Notification types

  • nano.confirmation identifies a matching cemented block.
  • nano.stream_reset means that the event cursor is no longer continuous. Reconcile before processing later events.
  • Use params.hash as the idempotency key. Store it and ignore duplicates.
  • params.subtype identifies a state send or receive when the node provides it.

Stream limits

  • The stream does not emit aggregate balances, derived balance events, votes, or telemetry.
  • A client must handle a confirmation that was not delivered.
  • Balance responses use receivable, not a pending field.

Track a recipient before sending

  1. Open GET /events/confirmations?accounts=<account>[,<account>]. Keep the connection open.
  2. After the stream opens, call accounts_balances once with the watched accounts and include_only_confirmed: true. Store each result.balances[account] value.
  3. Submit the block with process. Persist result.hash as the submitted block hash.
  4. When nano.confirmation.params.hash equals that hash, mark the submission cemented. A recipient filter matches an incoming state send through params.destination.
  5. After each matching confirmation, call accounts_balances once for the complete watched set. Publish each returned balance and receivable value. This is event-triggered batch refresh, not polling.
  6. Save the SSE id: value. Send it as Last-Event-ID when reconnecting.

SSE request

GET https://<gateway>/events/confirmations?accounts=nano_...%2Cnano_...
Accept: text/event-stream

Batch state request

{
  "jsonrpc": "2.0",
  "method": "accounts_balances",
  "params": {
    "accounts": [
      "nano_...",
      "nano_..."
    ],
    "include_only_confirmed": true
  },
  "id": 1
}

Read the batch balance result

PathTypeMeaning
result.balancesobjectOne entry for each requested account. It is not a total.
result.balances[account].balancestringCemented account balance in RAW.
result.balances[account].receivablestringCemented incoming sends not yet received, in RAW.
result.errors[account]string, optionalNative per-account validation error.

params.block.balance is the balance of params.account after that block. For a send addressed to a watched recipient, it is the sender balance. Use accounts_balances for the full balance and receivable state of the recipient.

Handle a missing notification or reset

  1. When a submitted hash has no confirmation after about 5 seconds, call block_info with that hash.
  2. Read result.confirmed. A value of true means the block is cemented.
  3. When nano.stream_reset arrives, refresh all watched accounts with accounts_balances before applying new confirmations.
  4. Use block_info for each submitted hash whose terminal state remains unknown.

Check the current account frontier

Use this sequence when you have an account but no submitted block hash. It checks whether the current frontier for that account is cemented.

  1. Call account_info for the account.
  2. If result.opened is false, the account has no frontier.
  3. Read result.frontier. This is the current frontier and can be ahead of cemented state.
  4. Call block_info with that hash. Read result.confirmed.
  5. Use result.confirmed_frontier and result.confirmed_balance when you need the last known cemented account state.

The fallback delay and frontier sequence follow the Nano confirmation-tracking guidance. The gateway exposes the methods linked above.

SSE notification

nano.confirmation

A block from the configured Nano profile has been cemented.

Notification

{
  "jsonrpc": "2.0",
  "method": "nano.confirmation",
  "params": {
    "account": "nano_sender...",
    "block": {
      "link_as_account": "nano_new_account...",
      "subtype": "send",
      "type": "state"
    },
    "confirmation_type": "active_quorum",
    "destination": "nano_new_account...",
    "hash": "ABC123",
    "profile": "nano-node/V28.2",
    "subtype": "send"
  }
}
SSE notification

nano.stream_reset

The stream lost continuity. Reconcile before processing more events.

Notification

{
  "jsonrpc": "2.0",
  "method": "nano.stream_reset",
  "params": {
    "profile": "nano-node/V28.2",
    "reason": "replay_unavailable",
    "reconcile": "Query authoritative Nano RPC state before applying new confirmations"
  }
}
